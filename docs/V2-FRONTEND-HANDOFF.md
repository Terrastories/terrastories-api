# V2 frontend handoff

## 1. Purpose and status

This is the durable brief for the future frontend project. It rebuilds the old Rails UI on top of the Terrastories V2 API. The frontend starts after the API is finished.

- Status: draft. Written 2026-11-22. The product owner agreed with all recommendations in the UI research memos. They are recorded as decisions in section 2.
- Sources: the Rails UI interaction list, the decision memo, the tiles memo, and `docs/V2-ROUTE-REGISTRY.md`. Routes were checked against the registry and `src/hono-app.ts`.
- Persona codes: PUB public visitor, VIE viewer, MEM member, EDI editor, ADM community admin, SUP super_admin.
- "Journey step" means the name of a persona step in the API QA fixture that proves the route. "none" means no step exists. "(+N)" means N more steps.
- Interaction IDs (A01, M01, B01, C01, D01, S01, V01) come from the Rails interaction list. Keep them in tickets so work traces back.
- Facts not verified against source are labelled "inferred" or "unverified" in section 3.

## 6. Map and tiles

### 6.1 What the API gives the client

- Map config: `GET /v2/community/map-config` (signed in) or `mapConfig` in `GET /v2/public/communities/:slug` (anonymous). Write: `PUT /v2/community/map-config` (admin).
- Fields: centre, zoom, pitch, bearing, bounds, projection, `styleUrl`, `mapboxStyleUrl`, `mapboxAccessToken` (public `pk.*` token), `mapbox3d`, `protomapsBasemapStyle`, plus authenticated-only `exposeMapboxCredentials` and `protomapsApiKey`. Antimeridian-wrapped bounds (sw longitude greater than ne longitude) are valid.
- Public reads (`GET /v2/public/communities/:slug` and `/explore/communities/:slug`) include `mapboxStyleUrl` and `mapboxAccessToken` only when `exposeMapboxCredentials === true` and the community is `public` (toggling visibility to `private` atomically resets `exposeMapboxCredentials = false`). Authenticated reads (`GET /v2/community/map-config`) include them and fall back to instance `MAPBOX_ACCESS_TOKEN` when unset. Offline mode ignores Mapbox and Protomaps keys.
- `styleUrl` is served only when it is a credential-free http or https URL (`sanitizePublicStyleUrl`). It is nullable.
- UI renders `mapboxStyleUrl` via `mapbox-gl` or MapLibre with `mapboxAccessToken` when set, falling back to OpenFreeMap "liberty" when unset.
- Story lists return map points, capped at 2000. Filters and sort are server-side. Clustering (Rails used max zoom 14, radius 50), cluster zoom and fit-bounds on filter stay in the client.
- Map points are places. Match each story to its points by joining the story's `places[].id` to the point id, not by story id or title (Rails matched by title and collided).

### 6.4 Rules for the client

- Every style that must work offline needs its glyphs and sprite on the same origin or the LAN. A public URL will not do.
- OpenFreeMap styles point at their own glyph and sprite URLs. For offline use, host the style JSON, glyphs and sprite yourself.
- Always show attribution. MapLibre reads it from the style, so do not hide it. OpenFreeMap: "OpenFreeMap © OpenMapTiles Data from OpenStreetMap". Tiles from OSM data need "© OpenStreetMap contributors".
- Test HTTP Range on any host that serves PMTiles. A CDN corrupted Range requests for the MapLibre demo tiles on GitHub Pages.
- Fonts: Protomaps basemaps-assets (SIL OFL), OpenMapTiles fonts, or VersaTiles fonts (MIT repo). All can be self-hosted.

### 6.5 Proposed fallback chain and override (inferred, not built)

1. Community `styleUrl`, when set.
2. Deployment default style (client config today; an API `DEFAULT_STYLE_URL` is proposed, see O9).
3. Bundled minimal world style (demotiles).
4. On an offline field kit, ignore or flag community styles that point to the internet.

Accepted `styleUrl` forms (proposal): absolute https, http for LAN, or a relative path. Reject credentials in the URL and query params named `key`, `token`, `access_token` or `apikey`. For a keyed provider, store a `{key}` placeholder and fill it from the client deployment config (O15). Satellite is a separate optional style with a toggle.

### 6.6 Cutover risk

Mapbox styles (`mapboxStyleUrl`, public `pk.*` `mapboxAccessToken`, `exposeMapboxCredentials`, `mapbox3d`) and Protomaps fields (`protomapsApiKey`, `protomapsBasemapStyle`) are supported in V2 `map-config`; the UI renders Mapbox styles via `mapbox-gl` or MapLibre with token, and OpenFreeMap remains the default when unset. Cutover validations must still ensure migrated tokens are public `pk.*` tokens (secret `sk.*` tokens are rejected with `422`) and that offline field kits fall back cleanly to local PMTiles/default styles.

## 7. Auth and security notes for the client

### 7.1 Cookies and CSRF

- Session cookie is `ts_session`: `HttpOnly`, `SameSite=Strict`, `Secure` (not on dev or the field-kit plain-HTTP opt-in), path `/`. Script cannot read it. Call the API with credentials included.
- Every non-GET, HEAD or OPTIONS request is checked. The `Origin` header must match `PUBLIC_ORIGIN` or be in `CORS_ORIGINS`. A `Sec-Fetch-Site: cross-site` request needs an allowed Origin. Failure returns `403 { "error": "Forbidden" }`.
- Deploy the UI on an origin listed in `PUBLIC_ORIGIN` or `CORS_ORIGINS`. Because the cookie is `SameSite=Strict`, host the UI on the same site as the API (inferred; confirm in spike S2). CORS allows only the `Content-Type` request header.
- Every response sends `Cache-Control: no-store`, `nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`. Media adds `Content-Disposition: attachment`. See spike S3.
- Sessions renew on use. A session can be a standard session (12-hour idle window) or a device session (login option `deviceSession`, fixed absolute lifetime). Show the "remember this device" choice and the sessions panel (V11).

### 7.2 Login and Argon2id

- Login is two steps. `POST /v2/auth/prelogin` returns `{ algorithm, salt, params }`. Unknown identifiers get a deterministic fake of the same shape, so the UI cannot tell them apart. The browser derives the key, then `POST /v2/auth/login` sends `{ identifier, communitySlug?, derivedKey, upgrade?, deviceSession? }`.
- Parameters: Argon2id, m=19 MiB, t=2, p=1. Run in a web worker. Show progress. SPEC target: p95 at most 3 s on a 2 GB Android.
- `communitySlug` only disambiguates an email that matches more than one account. The API answers an ambiguous email with the same uniform failure. Offer an optional community field on the login form, and do not explain why a login failed.
- Failures are uniform and non-enumerating (401 or 400). Throttled accounts are refused even with the right key. Show one generic "try again later" message.
- Legacy Rails bcrypt accounts (prelogin `algorithm` is `client-bcrypt-rails+sha256`): the client recomputes the bcrypt hash string from the password with the prelogin `salt` and cost (bcrypt reads at most 72 bytes of the password, so truncate to 72 bytes) and sends it as `derivedKey`. The same request must carry `upgrade: { algorithm, salt, params, derivedKey }` with fresh Argon2id material: `algorithm` `client-argon2id+sha256`, a new 16-byte base64 `salt`, the canonical policy `params`, and the 64-hex Argon2id key derived with them. Without a valid `upgrade` the login is rejected (401). On success the server stores the Argon2id verifier. Cover this path in the login spike.
- Argon2id is also needed for password change (`POST /v2/auth/password`), admin-set passwords, bootstrap, claim, recovery redeem, and step-up.
- The registry notes that login on `main` may still use a transitional body (`{ email, password, communityId? }`). Confirm the live contract before building.

### 7.3 Step-up

- Sensitive actions re-verify the current password in the same request: change password, generate recovery codes, designate steward, cancel a steward notice, request erasure, request community withdrawal, and the planned username and email change (D04). Withdrawal and erasure need `currentDerivedKey` (`verifyStepUp`) unless an admin is on a fresh `admin_issued` session; a designated steward must always send the password.
- Recovery-code generation can skip the password only on a fresh `admin_issued` code session (15 minutes, one-shot). A second verifier-free regeneration is rejected.
- Build one reusable step-up dialog that derives the key in the worker and posts it with the action.

### 7.4 Recovery-code gate

- A community admin with no active recovery codes gets `403 { "error": "Recovery codes required", "code": "recovery_codes_required" }` on every route outside `/v2/auth/*`.
- `GET /v2/auth/me` reports `recoveryCodesConfirmed`. On login, and on any 403 with that code, route the admin to the recovery-codes screen (V07, V08). Codes are shown once: offer copy, print and download.
- The gate applies to the `admin` role in a community. It is controlled by a server option, so test against a server where it is on.
- Initial codes also arrive in the `POST /v2/bootstrap` and `POST /v2/bootstrap/claim` responses. Show them at once.

### 7.5 Errors and conventions

- Envelope: `{ error, code?, details? }` (D22). Hidden or cross-community rows return `404 { "error": "Not found" }`. Role-blocked route families return `403 { "error": "Forbidden" }`. Do not tell the user which one a hidden row was.
- Disabled and withdrawn communities: the sovereignty status route stays reachable. A withdrawn community needs a "only export is available" state.
- IDs: core entities are positive integers. Files are UUIDs. `Content-Type: application/json` is required on JSON writes (else 415).
- Timestamps: ISO 8601 (D23).
